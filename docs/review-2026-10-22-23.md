## Findings so far (core/conversation/ConversationRecorder.kt)

1. **High: recorded audio is zeroed during playback.** Line ~534 is `writer?.write(effectiveChunk)`.
   12dabf1 fixed this ("preserve recorded audio chunk"), but eedcd60 put it back. Playing any clip
   while recording writes silence to *both* streams' WAV files for the clip's length plus 1.5 s. The
   user's speech and the call are lost from disk, not only from transcription. A channel mute also
   writes silence; that may be intended for privacy, but it should be decided explicitly.
2. **High: live word times drift after playback or mute.** While muted or playing, chunks are *not sent*
   to the live session (`if (!playing && !isMuted) session.sendAudio`), but `samplesSentToLive`
   still advances. The live server's clock then falls behind the stream, and later `settle()` maps
   word times from `liveStartSample` to the wrong place. The start of every later segment, and so the
   audio clip sent for accurate refinement, points too early by the muted duration. Fix: send the
   zeroed `effectiveChunk` instead of skipping it.
3. **High: duplicate transcription around reconnects.** 45bc31a changed `else if (liveUnavailable)` to
   `else`, so while live is connecting or reconnecting the segmenter announces clips. Then, on
   connect, the rolling buffer's gap (up to 10 s) is replayed to the live session (28a3668). The same
   speech becomes a clip segment and a live segment. In live-only mode (provider None) those clips
   also raise NoSpeechService or failures. `updateDetectedLanguage` reconnects live every time the
   detected language flips (ar↔en), which makes this frequent.
4. **Medium: the echo filter can drop real call speech.** `applySegment` drops a SYSTEM segment when a
   mic segment within 12 s matches it by Jaccard ≥ 0.6 with ≥ 2 shared words, or by containment, so
   short common replies ("ok thank you") from the other side vanish. The check is one-sided: a38ab55
   removed the retroactive mic-side check.
5. **Medium: unsynchronized state.** `detectedLanguage` is written from up to 3 concurrent transcription
   coroutines. `switchLiveLanguage` and `updateDetectedLanguage` launch close+connect that can race
   with the capture loop's own `connectLive()`.
6. **Low: `SpeechSegmenter` defaults changed** (a38ab55: silence 700→1400 ms, max 15→25 s). Longer
   lines and later cards; check the tests and docs still describe this.
7. **Low: `JavaSoundAudioBackend.open` now retries 4× with `Thread.sleep(250)`.** It blocks up to 1 s on
   the IO thread; acceptable, but note it.
