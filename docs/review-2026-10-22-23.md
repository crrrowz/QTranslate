## Findings so far (core/conversation/ConversationRecorder.kt)

1. **High: recorded audio is zeroed during playback.** Line ~534 is `writer?.write(effectiveChunk)`.
   12dabf1 fixed this ("preserve recorded audio chunk"), but eedcd60 put it back. Playing any clip
   while recording writes silence to *both* streams' WAV files for the clip's length plus 1.5 s. The
   user's speech and the call are lost from disk, not only from transcription. A channel mute also
   writes silence; that may be intended for privacy, but it should be decided explicitly.
2. **High: live word times drift after playback or mute.** While muted or playing, chunks are *not sent*
   to the live session (`if (!playing && !isMuted) session.sendAudio`), but `samplesSentToLive`
   still advances. The live server's clock then falls behind the stream, and later `settle()` maps
   word times from `liveStartSample` to the wrong place. The start of every later segment, and so the
   audio clip sent for accurate refinement, points too early by the muted duration. Fix: send the
   zeroed `effectiveChunk` instead of skipping it.
3. **High: duplicate transcription around reconnects.** 45bc31a changed `else if (liveUnavailable)` to
   `else`, so while live is connecting or reconnecting the segmenter announces clips. Then, on
   connect, the rolling buffer's gap (up to 10 s) is replayed to the live session (28a3668). The same
   speech becomes a clip segment and a live segment. In live-only mode (provider None) those clips
   also raise NoSpeechService or failures. `updateDetectedLanguage` reconnects live every time the
   detected language flips (ar↔en), which makes this frequent.
4. **Medium: the echo filter can drop real call speech.** `applySegment` drops a SYSTEM segment when a
   mic segment within 12 s matches it by Jaccard ≥ 0.6 with ≥ 2 shared words, or by containment, so
   short common replies ("ok thank you") from the other side vanish. The check is one-sided: a38ab55
   removed the retroactive mic-side check.
5. **Medium: unsynchronized state.** `detectedLanguage` is written from up to 3 concurrent transcription
   coroutines. `switchLiveLanguage` and `updateDetectedLanguage` launch close+connect that can race
   with the capture loop's own `connectLive()`.
6. **Low: `SpeechSegmenter` defaults changed** (a38ab55: silence 700→1400 ms, max 15→25 s). Longer
   lines and later cards; check the tests and docs still describe this.
7. **Low: `JavaSoundAudioBackend.open` now retries 4× with `Thread.sleep(250)`.** It blocks up to 1 s on
   the IO thread; acceptable, but note it.

## Findings from the remaining items (plugins, UI, script, rules)

Numbering continues from above. Ordered by severity.

### High

8. **Refocusing the conversation window reconnects live recognition on both streams.**
   `ConversationWindow.kt:522-525` calls `loadPreferences()` on every `windowActivated`. Its `fill()`
   (`:768-774`) sets `selectedItem`, and `JComboBox` fires `ActionEvent` even when the value does not
   change. The combo listeners (`:499-514`) then call `recorder.updateSpokenLanguage`/`updateCallLanguage`
   while recording. They call `switchLiveLanguage` (`ConversationRecorder.kt:290-300, 705-711`), which
   closes and reconnects the live session unconditionally. So every click back into the window, and
   every dismissed dialog (the save prompt, a retry message), restarts live text for both sources and
   replays the gap, which makes finding 3 (duplicates) frequent. Fix: ignore events while filling, and
   switch only when the language actually changed.
9. **OpenAI Realtime live text cannot work as written** (`OpenAiRealtimeService.kt`).
   - It sends 16 kHz PCM (`:73-77`), but the Realtime API's `pcm16` is 24 kHz mono, so the audio arrives
     at 1.5x speed.
   - The model comes from the *accurate* provider's `model` field (`:54, :64`). With Groq set to
     `whisper-large-v3-turbo`, the socket opens `?model=whisper-large-v3-turbo` and fails. The name
     is also not URL-encoded.
   - It opens a conversation session (server VAD, `create_response` defaulting to true, `:110`), so the
     model *answers* every utterance, and that is billed. Partials are read from
     `response.audio_transcript.delta` (`:190`), the assistant's output rather than the user's speech.
   - It should use a transcription session (`input_audio_transcription` deltas) at 24 kHz with its own model.
10. **666b2f3 removed the external Vosk server engine.** The user's VM container `vosk-stt`
    (ws://192.168.85.129:8765) can no longer be used. A saved `Vosk (local server)` engine is silently
    migrated to the built-in engine (`SpeechPlugin.kt:40-42`), and `liveServerUrl` is dropped. The
    built-in engine needs a local model; Arabic is 318 MB or 1.3 GB, and finding 12 stores it twice.
    Restoring it is a product decision; the old `VoskLiveSession` is in `git show 666b2f3^`.

### Medium

11. **Plugin action buttons write unsaved values into the live settings object.**
    `DynamicPluginSettingsDialog.kt:319-326` (07451aa) copies every on-screen field by reflection into
    `settingsInstance`. That is `plugin.getSettings()` (`PluginManager.kt:337-340`), the object the
    running plugin reads. Clicking "Download/Check Model" therefore applies uncleaned, unvalidated and
    unpersisted Mode, URL and keys immediately, and Cancel does not undo it. Fix: copy the values into a
    `copy()` of the settings and invoke the action on that.
12. **Every Vosk model is stored twice.** `VoskModelManager.kt:53-60, 175-180, 417-423, 212-223` copy each
    download or import into the plugin data dir *and* into a hard-coded
    `%APPDATA%/QTranslate/plugins_data/speech-services/vosk-models`. The Arabic large model then takes
    over 2.6 GB, and the portable build writes outside its own folder.
13. **The Vosk model cache can double RAM and close a model in use** (`VoskBuiltinService.kt:107-126, 209-223`).
    - The same model can be cached under two keys: `preloadModel` uses the `modelsDirectory` path, while
      `findModelForLanguage` may return the persistent copy's path.
    - `preloadModel`'s `computeIfAbsent` bypasses the 2-model cap.
    - `getOrLoadModel` reads the cache without the lock (`:110`), so another thread's eviction can
      `close()` that handle just before `createRecognizer`. That is a native use-after-free and can
      crash the JVM.
14. **Live Vosk sessions leak a native recognizer and a thread when finish times out.** `closeLive` wraps
    `session.finish()` in `withTimeoutOrNull` (`ConversationRecorder.kt:697-700`). If the worker is
    still chewing the replayed gap (up to 10 s of audio), `processingJob.join()` is cancelled, so
    `getFinalResult` and `cleanup()` never run (`VoskBuiltinService.kt:303-316`). Because `ended` is
    already true, a later `cancel()` does nothing. Each reconnect (finding 8) can leak one.
15. **Deepgram live drops while muted or playing.** Nothing sends `KeepAlive`, and the recorder stops
    sending audio while muted or playing (finding 2), so Deepgram closes the socket after about 10 s
    (NET-0001). The reconnect then replays the gap and produces duplicates (finding 3). Also,
    `detect_language=true` (`DeepgramLiveService.kt:134-138`) is documented for pre-recorded audio
    only (streaming uses `language=multi`), and no `model=` is sent, so the account default is used.
16. **"Application" capture mode records the whole output device.** `wasapi-loopback.ps1` `list-apps`
    only maps a process to its device. `Capture` (`:228-`) is plain device loopback, and the UI picks
    the device of the chosen app (`ConversationWindow.kt:816-848`). Choosing Discord also records
    YouTube, notifications and anything else on that device. Either use process loopback
    (`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`, Windows 10 2004+) or label it as a device picker.
17. **Hard-coded English UI text** (AGENTS.md localization rule): `ConversationWindow.kt:183, 189, 195,
    201, 206, 209, 529` (mute tooltips, "Newest/Oldest at top") and `:1037-1039` ("Play audio",
    "Re-transcribe segment", "Delete message"). They need keys in embedded_en, en-GB and ar-SA.

### Low

18. Retrying a segment of a *saved* session that then fails leaves it on screen as an empty pending
    line until the session is reopened (`ConversationWindow.kt:1276-1297`: `interim` clears the text,
    and nothing restores it when `retry` returns null).
19. `SpeechRecognitionService.metadata.requiresConfiguration` is true only in Cloud mode
    (`SpeechPlugin.kt:146`), so in Hybrid, which also needs a Groq key, the plugin dialog shows no
    Test button (`PluginsPanel.kt` `onTestConnection`).
20. `onEnable` preloads the model in an unowned `CoroutineScope(Dispatchers.IO)` (`SpeechPlugin.kt:69`).
    A disable during the load closes the cache first, and the model loaded afterwards is never freed.
    Changing the model in settings does not preload the new one.
21. Resumable download: if a `.part` already holds the whole file, the loop still asks for
    `Range: bytes=<size>-` because it compares against the approximate catalogue `sizeBytes`
    (`VoskModelManager.kt:322-336`). The server answers 416, and every retry fails until the `.part` is
    deleted by hand. The manual redirect loop also follows https->http and does not resolve relative
    `Location`s.
22. `formatVoskText` turns every standalone `i` into `I` for every non-Arabic language
    (`VoskBuiltinService.kt:362-368`), which is wrong for Italian ("i ragazzi") and others.
23. OpenAI Realtime `connect` treats a 10 s ready timeout as success (`OpenAiRealtimeService.kt:151`).
24. Dead or inconsistent code: the `LiveEngine` enum (`SpeechProvider.kt`) is unused, and Local-only
    mode still offers Deepgram/OpenAI in the live-engine dropdown (and then refuses them).
25. 59333a9 raised the portable budget from 55 to 98 MB and the bundled-plugins budget from 3 to 45 MB,
    because the speech plugin's shadowJar carries Vosk natives for every OS. A Windows-only build could
    drop most of that.
26. 3ef13c4 edited the tracked `.gitignore`/`.ignore` graft lines (AGENTS.md says not to touch them). It
    undid an earlier accidental commit, so the net effect is acceptable. The working tree currently has
    an uncommitted `.gitignore` change that this review did not make and did not touch.
